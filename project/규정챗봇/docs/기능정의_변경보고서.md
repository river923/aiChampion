# 규정챗봇 기능정의 및 변경보고서

이 문서는 규정챗봇의 기능 정의, 설계 결정, 변경 이력을 누적 관리하기 위한 기준 문서다. 향후 프롬프트나 구현 변경으로 이미 확정된 작은 기능이 흔들리지 않도록, 기능 단위로 상태와 변경 사유를 기록한다.

## 관리 원칙

- 기능은 가능한 작은 단위로 정의한다.
- 기능마다 입력, 출력, 실패 조건, 보안 조건을 기록한다.
- 확정된 기능은 직접 수정하지 않고 정책 모듈 또는 어댑터를 추가해 개선한다.
- 변경이 필요하면 변경 전후 동작과 영향 범위를 기록한다.
- 모든 기능은 테스트 기준을 함께 가진다.

## 기능 상태

- `초안`: 아이디어 또는 설계 초안
- `검토중`: 사용자 검토 중
- `확정`: 구현 기준으로 사용 가능
- `변경검토`: 기존 확정 기능의 변경 필요성이 생김

## 기능 정의

| 기능명 | 상태 | 목적 | 핵심 동작 | 실패 조건 | 보안 조건 |

| 문서 파싱 | 검토중 | HWP/HWPX/PDF를 Markdown으로 변환 | `kordoc`으로 로컬 변환 후 파싱 결과 저장 | 변환 실패, 미지원 확장자 | 외부 온라인 변환 금지 |

| 근거 기반 답변 | 검토중 | 환각 없는 답변 생성 | 확정 근거만 LLM에 전달 | 근거 없음, 출력 검증 실패 | LLM 출력 재검증 |

| 캐릭터 문서 업로드 | 검토중 | 캐릭터별 최신 규정 관리 | 최대 10개 문서 업로드 및 최신본 활성화 | 미지원 확장자, 10개 초과 | 원본문서 Git 제외 |
| 업무 범위 라우팅 | 검토중 | 적합한 AI 캐릭터 추천 | 공유 카탈로그에서 후보 캐릭터 검색 | 적합 캐릭터 없음 | 캐릭터별 문서 범위 준수 |
| LLM 어댑터 | 검토중 | 공급자 교체 가능 구조 | provider API 기반 실제 호출 | 키 없음, 공급자 오류 | API 키 암호화 저장 |
| LLM API 키 관리 | 검토중 | 관리자 화면에서 공급자별 키 관리 | API 키 입력, 암호화 저장, 연결 테스트 | 권한 없음, 키 형식 오류 | 원문 재표시 금지 |
| 조직도 관리 | 검토중 | 데모 조직도와 캐릭터 배치 관리 | 조직, 부서, 사용자, 캐릭터 추가/삭제 | 권한 없음, 중복 노드 | 개인정보 마스킹 |
| Electron 데모 | 검토중 | 사내 메신저형 시연 | 로그인, 조직, 캐릭터, 대화, 근거 패널 표시 | 백엔드 연결 실패, 미로그인 | Node.js API renderer 미노출 |
