# [Codex] 리팩토링 관점 프로젝트 점검

**1. 작업 내용 (Content)**
- `docs/handovers/2026-06-11_1638_Antigravity_로컬LLM연동_UI개편.md`를 확인해 직전 세션 맥락을 파악했다.
- `README.md`, `backend/chat/services.py`, `backend/chat/views.py`, `backend/llm/providers.py`, `desktop/electron-demo/main.js`, `desktop/electron-demo/renderer/renderer.js`, 주요 테스트 파일을 기준으로 리팩토링 관점 점검을 수행했다.
- 코드 수정은 하지 않았고, 점검 결과를 사용자에게 보고하기 위한 진단만 수행했다.

**2. 완성도 (Completion)**
- 리팩토링 점검 목표는 완료했다.
- 주요 결론은 다음과 같다.
  - `backend/chat/services.py`는 답변 오케스트레이션, 검색, 프롬프트 생성, LLM 응답 파싱, 인용 검증, 담당자 안내, 감사 로그 기록이 한 파일/함수에 결합되어 있어 최우선 분해 대상이다.
  - `backend/llm/providers.py`는 공급자별 어댑터와 로컬 모델 생명주기 관리가 함께 있어 테스트와 장애 격리가 어렵다.
  - `desktop/electron-demo/renderer/renderer.js`와 `styles.css`는 250줄을 초과해 UI 상태, API 호출, 렌더링 컴포넌트 분리가 필요하다.
  - 프로젝트 안에 `backend/build`, `backend/dist`, `backend/db.sqlite3`, `backend/models/*.gguf`, `desktop/electron-demo/node_modules`, `desktop/electron-demo/dist`, `.DS_Store`, `__pycache__` 등 생성물/대용량 파일이 섞여 있어 배포/저장소 위생 정리가 필요하다.

**3. 발생한 에러 및 미해결 문제 (Errors & Issues)**
- `./.venv/bin/python backend/manage.py check`는 통과했다.
- `./.venv/bin/python -m pytest backend`는 컬렉션 중 실패했다.
  - `backend/test_chat.py`가 모듈 import 시점에 DB를 조회한다.
  - `backend/test_parse.py`도 모듈 import 시점에 DB를 조회한다.
  - pytest-django가 DB 접근을 막으면서 `Database access not allowed` 오류가 발생했다.
- 앱 테스트만 따로 실행한 `./.venv/bin/python -m pytest backend/chat/tests.py backend/documents/tests.py backend/indexing/tests.py backend/secretstore/tests.py`도 1건 실패했다.
  - `backend/chat/tests.py::test_ask_question_when_evidence_exists_but_secret_missing`
  - 원인: `OrganizationUnit.objects.create(...)`로 `treebeard.MP_Node` 모델을 직접 생성해 `depth` NOT NULL 제약을 위반한다. 테스트 fixture는 `add_root`/`add_child` 기반으로 바꿔야 한다.
- `desktop/electron-demo`에는 `npm test` 스크립트가 없다.

**4. 원래 계획 대비 변경된 사항 (Changes & Workarounds)**
- 사용자의 요청이 "리팩토링 관점 점검"이었으므로 실제 리팩토링 구현은 진행하지 않았다.
- Git 저장소가 아니어서 `git status` 기반 변경 추적이나 추적 파일 점검은 수행할 수 없었다.
- `rg` 검색 중 Electron `dist` 산출물까지 검색 대상에 포함되어 출력이 과도해졌다. 이는 산출물 격리/ignore 정리가 필요하다는 근거로 보인다.

**5. 다음 작업자 추가 수행 사항 (Next Steps)**
- 1순위: `backend/test_chat.py`, `backend/test_parse.py`를 pytest 컬렉션 대상에서 제외하거나 관리 명령/수동 진단 스크립트로 이동한다.
- 2순위: `backend/chat/tests.py`의 조직 fixture를 `OrganizationUnit.add_root`/`add_child` 방식으로 수정해 앱 테스트를 녹색으로 만든다.
- 3순위: `.gitignore` 또는 배포 산출물 정리 정책을 추가해 DB, 모델, 빌드 결과, 캐시, `node_modules`, `.DS_Store`가 작업 대상에 섞이지 않게 한다.
- 4순위: `backend/chat/services.py`를 `retrieval`, `prompt_builder`, `llm_response_parser`, `citation_validator`, `audit_writer` 수준으로 나누고 각 순수 함수부터 단위 테스트를 추가한다.
- 5순위: `backend/llm/providers.py`를 공급자별 어댑터와 로컬 모델 로더로 분리하고, 로컬 모델 선택 로직과 오류 메시지 마스킹을 테스트한다.
- 6순위: Electron 렌더러를 API 클라이언트, 상태 관리, DOM 렌더링 모듈로 분리하고 IPC 요청 검증 테스트를 추가한다.
