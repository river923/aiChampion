# LLM 협업 및 인수인계 지침

본 프로젝트는 여러 LLM(Codex, Antigravity(초초) 등)이 교대로 개발에 투입될 수 있습니다.
LLM 간의 맥락 단절, 작업 충돌, 중복 개발을 방지하기 위해 **모든 작업 세션 종료 시 반드시 인수인계 문서(.md)를 작성**하여 다음 LLM이 확인할 수 있도록 합니다.

## 1. 인수인계 파일 저장 위치 및 명명 규칙
- **저장 위치:** `프로젝트/규정챗봇/docs/handovers/`
- **파일명 규칙:** `YYYY-MM-DD_HHMM_[작업LLM명]_작업요약.md`
  - 예시: `2026-06-11_1330_Antigravity_파싱모델구현.md`
  - 예시: `2026-06-12_0900_Codex_ElectronUI수정.md`

## 2. LLM 작업 시작 시 "필수" 행동 (행동 강령)
모든 LLM은 개발에 투입되어 코딩을 시작하기 전에 **반드시 아래 순서대로 맥락을 파악**해야 합니다.
1. `docs/handovers/` 폴더 내의 **가장 최신 문서**를 읽고, 이전 LLM의 완성도와 에러 내역을 파악합니다.
2. 이전 작업자가 작성한 `5. 다음 작업자 추가 수행 사항 (Next Steps)`을 바탕으로, 이번 세션의 작업계획서 초안을 작성하여 강과장님께 '승인'을 요청합니다.

## 3. 인수인계 문서 작성 템플릿
실제 개발 과정에서는 원래 계획(`작업계획서.md`)대로 풀리지 않는 경우가 많습니다. 계획 대비 변경된 사항이나 해결하지 못한 에러를 **투명하게 기록**하는 것이 가장 중요합니다.

작업이 끝나거나 리밋/오류 등으로 세션이 종료되기 직전, 아래 템플릿을 복사하여 문서를 작성합니다.

---

### [복사해서 사용할 템플릿]

# [[작업LLM명]] 작업 요약 (예: [Antigravity] 문서 파싱 모델 및 인덱스 로직 구현)

**1. 작업 내용 (Content)**
- (오늘 세션에서 진행한 구체적인 작업 내역 기록. 핵심 수정 파일명 명시)
- 예: `backend/documents/models.py`에 문서 모델 작성.

**2. 완성도 (Completion)**
- (목표 대비 달성도 및 현재 단계 기록)
- 예: "Phase 2 문서 파싱 파이프라인 중 70% 완료"

**3. 발생한 에러 및 미해결 문제 (Errors & Issues)**
- (현재 발생 중인 에러, 예외, 테스트 실패 항목 등을 상세히 기록)
- 예: "Electron에서 IPC 통신 시 컨텍스트 격리 권한 오류 발생 중. 아직 미해결."

**4. 원래 계획 대비 변경된 사항 (Changes & Workarounds)**
- (기존 `작업계획서.md`나 초기 설계와 다르게 우회하거나 변경한 사항 기록)
- 예: "LLM 공급자 연동이 막혀서 일단 로직만 작성하고 Mock 데이터로 테스트하도록 우회함."

**5. 다음 작업자 추가 수행 사항 (Next Steps)**
- (다음 LLM이 이어서 반드시 해결하거나 시작해야 할 작업 목록 명시)
- 예: "1. IPC 통신 권한 오류부터 해결할 것. 2. 이어서 `orgs` 조직도 모델 생성할 것."
